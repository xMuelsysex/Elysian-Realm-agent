# 基准测量：延迟 / 吞吐 / 保真度 / 记忆率

## 目标与决策

- 目标：为主人提供**可复现的实测数据**（延迟、吞吐、准确率、成本、规模），而不是测试数量这类间接指标；并额外核对记忆系统的命中率与治理退役率。
- 决策一：新增两个独立基准脚本，不引入测试框架、不写状态、不访问网络。`scripts/bench.mjs`（延迟/吞吐/保真度/OOC 准确率）、`scripts/bench-memory.mjs`（记忆命中率/排序不变量/治理退役率/写入边界）。
- 决策二：记忆语料标注为「每条查询有唯一正确答案」——只有目标记录含该话题词，其余记录只共享主题词；分 easy（目标与干扰项同龄同重要性）与 hard（目标最旧最不重要、干扰项最新最重要）两个子集，避免只测出「词命中」这种平凡结论。
- 决策三：治理退役率与写入边界**走真实 `RealmHost.govern` / `RealmStateStore.applyMemoryWrites`**，不在基准里复制规则，避免基准与实现漂移。
- 决策四：OOC 准确率用两套数据——标注正例（测试套件里作者标注的泄漏样本，测召回）与**正史 17,665 条角色台词**（检测器未参与调参的留出集，测误报）。

## 计划

1. `scripts/bench.mjs`：记忆检索延迟 vs 规模、角色可见投影延迟、正史语料规模、台词检索、prompt 组装体积、OOC 召回/误报/吞吐、确定性 tick 吞吐与可复现性。
2. `scripts/bench-memory.mjs`：检索命中率（easy/hard + 年龄/重要性衰减）、6 条排序不变量、治理退役率、写入边界拒收率。
3. `npm run bench` 一条命令跑完两个脚本。
4. 基准暴露的缺陷按根因修复并补回归测试。

### 基准暴露的缺陷（已修）

`src/conversation/oocGuard.ts:13` 的指令覆盖模式末尾名词组可选，导致「我没有忘记之前你说的话」被判为 OOC 注入——角色回复会被宿主隔离、参与者消息会被整条丢弃。正史留出集 3 条误报里有 1 条正是此因。修法：末尾名词改为必需，中间允许不跨句读的 ≤4 字间隔以保住「忽略之前的所有指令」的召回。新增回归测试 `ooc guard catches instruction-override injections and passes ordinary forgetting`。

### 观察项（未改，待主人决策）

- 无重叠查询仍返回 topK 条：`retrieveMemoryRecords` 无零分过滤（recency/importance 恒正，故 finalScore 恒正），而 `retrieveLoreEntries` 有零分过滤。分数分解随命中返回，调用方可自行过滤。

## 结论

- 记忆检索与角色可见投影均为线性，约 9–11 µs/条与 1.35 µs/条；20k 记忆时单次检索 207 ms，与 memory-governance spec 的「清理到 <5k 保 <35 ms」结论一致。
- 台词检索 26.8 ms 是聊天链路里最重的一步确定性开销。
- 记忆命中率在「唯一相关 + 同龄同重要性」下满分；在对抗性设置（目标最旧且最不重要）下降到 75%，衰减发生在重要性而非年龄——相关性只占 50% 权重是既定取舍。
- 治理与写入边界经真实宿主核对，退役集合与期望精确一致、幂等、零删除。

## 附：与 GitHub 同类项目的可比性核对

新增 `scripts/bench-locomo.mjs`（`npm run bench:locomo`）：在公开 LoCoMo 数据集（`snap-research/locomo`，10 段对话 / 5,882 轮 / 1,982 个带 evidence 标注的问题）上测**纯检索的证据召回**，0 次 LLM 调用，所以数字可归因到检索器本身。数据缓存在 `.bench-data/`（已 gitignore）。

| 配置 | recall@1 | @5 | @10 | @20 |
|---|---|---|---|---|
| 默认权重（相关性 0.5 / 时间 0.3 / 重要性 0.2） | 7.5% | 18.2% | 24.2% | 32.3% |
| 纯词法（相关性 1.0） | 15.5% | 28.3% | 34.2% | 41.0% |

分类（recall@10，纯词法）：single-hop 49.0%、temporal 48.0%、adversarial 41.1%、multi-hop 14.6%、open-domain 13.5%。检索 p50 5.4–5.9 ms（约 590 轮/对话全量扫描）。

对照（均为各自发布口径，非同一指标）：Mem0 LoCoMo 92.5 / LongMemEval 94.4（LLM-as-Judge 问答准确率，托管平台，单遍检索 top_200，7.0K token，p50 0.88 s）；Zep DMR 94.8% vs MemGPT 93.4%，LongMemEval 最高 +18.5% 准确率、延迟 -90%。

- 结论：本项目的检索是**纯词法（CJK 二元组 + ASCII 整词）+ 加权评分**，无 embedding、无向量/图索引、无实体链接、无词干化，因此英文公开集上的证据召回明显弱于语义检索方案（34.2% @10 vs 它们的 LLM 裁判问答分）。这是能力差异，不是口径差异。
- 可操作发现：默认权重把相关性降到 0.5，在本数据集上损失 10 个点的证据召回（34.2% → 24.2%）——时间/重要性对「事实性回忆」是干扰，对「角色连续性」才是收益。
- 本项目在对照轴上独有的：tick 轨 0 LLM 调用且字节级可复现、5 个运行时依赖、角色表现边界（OOC）有确定性检测与正史留出集误报率。
