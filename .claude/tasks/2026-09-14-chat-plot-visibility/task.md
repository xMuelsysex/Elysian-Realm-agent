# 聊天设置返回与剧情可见性

## 目标与决策
- 在 `/admin` 设置页增加返回 `/chat` 的明确入口。
- 当前剧情不明显的根因是聊天页只有“已解锁到场景 N / 608”的弱状态提示，剧情 Lore 主要隐藏在 Prompt 中，普通聊天缺少可见的当前场景反馈。
- 复用现有 `storyProgress` 与已过滤的剧情数据，在聊天页展示当前档案可见的章节 / 场景导语，并强化 Prompt 的剧情连续性指令；不泄露未解锁场景，不新增独立剧情状态。

## 计划
- 修改 `src/service/adminPage.ts` 增加返回聊天入口。
- 修改 `src/host/chatPage.ts` 与必要的 Lore / Prompt 代码，显示当前档案剧情状态和当前可见剧情导语。
- 补充或调整最小回归测试，验证游标与角色入场边界仍然生效。
- 运行 focused 测试、类型检查、构建和浏览器检查。

## 验证记录
- `/admin` 返回聊天链接已通过浏览器点击验证，目标为 `/chat`。
- 游标 `0` 时聊天页只显示“当前剧情尚未解锁”；游标推进到 `1` 后显示章节“在无限的阴影之中”、场景“初入乐土”和解锁进度 `1 / 608`。
- 首次浏览器检查发现剧情卡片引用了未定义的 `appendText`；已补上聊天页局部辅助函数并重建，复测通过。
- `npm test`：283/283 通过；`npm run typecheck` 通过；浏览器使用独立临时数据目录和 `4326` 端口验证通过；控制台仅有既有 `/favicon.ico` 404。
- `npm run verify:e2e` 通过：SSE、JSON fallback、双角色、历史、关系、情绪、夜间叙事和反思全部通过；`git diff --check` 通过。

## 结论
- 设置页可直接返回聊天；聊天页对当前档案的剧情阶段有明确可见反馈，Lore 检索会保留最新已解锁且角色已入场的场景，并要求模型将其作为连续剧情使用；未解锁内容和角色入场边界保持不变。
