# 剧情测试台与模型上下文可视化

## 目标与决策

- 为现有 `/chat` 与 `/admin` 增加独立的 `/test` 测试台，不把调试信息塞入普通聊天界面。
- 测试台显示当前实际 LLM 的非敏感配置（Provider、Model、Base URL、配置来源、凭据来源），绝不返回 API Key。
- 测试台支持选择 `profileId`、角色和测试消息；预览请求只读展示本次检索到的可见剧情片段，发送测试才调用并持久化聊天。
- 剧情展示只返回角色实际可读取的命中行，不返回命中场景中未注入的完整台词；同时显示章节、场景、阶段、说话角色、文本类型、相关度、来源 URL 和注入模型的剧情上下文文本。
- 普通 `/chat` 保持现有界面，不强制每句回复提及剧情。

## 计划

1. 新增受现有 extension/token 机制保护的 `/test` 路由、模型状态和剧情预览 / 测试 API，并复用 `RealmHost` 的剧情检索边界。
2. 实现原生 HTML 测试台，加入 `/chat`、`/admin` 入口。
3. 补充接口与页面脚本测试，执行 focused 单测、类型检查、构建、E2E 和浏览器检查。

## 验证记录

- `npm run typecheck` 通过。
- `npm test` 通过，`285/285` 全部通过；覆盖测试扩展路由、模型状态不泄露 API Key、预览不持久化、角色入场边界和实际可见剧情行。
- `npm run verify:e2e` 通过，SSE、JSON fallback、双角色、历史、关系、情绪、夜间叙事和反思均正常。
- 独立临时 Host 浏览器实测 `/test`：游标 `0` 显示无剧情；游标 `80` 显示 3 个角色可见场景、说话角色、文本类型、来源 URL、相关度，并能展开实际注入的 `storyPrompt`；“发送并测试”显示模型回复和读取证据。
- `git diff --check` 通过；临时 Host 与 stub 已停止。浏览器仅有既有 `/favicon.ico` `404`。

## 结论

- 完成独立 `/test` 剧情测试台：展示实际模型元数据、档案 / 角色 / 消息选择、可见剧情片段和模型收到的剧情上下文；预览只读，发送测试才写入当前档案。
- 普通 `/chat` 保持干净，`/chat` 与 `/admin` 均提供测试台入口；API Key 不进入响应或页面。
- 未新增联网运行时依赖、剧情编辑能力或普通聊天的强制剧情输出。未创建 Git 提交。
