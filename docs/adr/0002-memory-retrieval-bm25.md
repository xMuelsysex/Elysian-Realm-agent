# 0002. 记忆检索升级为 BM25 多信号 + 英文词干归一化

- **Status**：Accepted（2026-09-18）
- **Context**：
  - 记忆检索的文本通道原本是朴素词元覆盖率（`|查询词 ∩ 记录词| / |查询词|`）：稀有词与常见词等权，`researching` 匹配不到 `research`，长记录也没有任何加权。结果是「同义改写、形态变化、具体细节」检索不到。
  - 同时，检索排序总分里相关性只占 0.5（时间 0.3 / 重要性 0.2），导致「唯一相关但既旧又不重要」的记忆经常输给「近期且高重要性的同主题干扰项」——实测该场景 recall@1 只有 75%。
  - 目标形态是 Mem0 式的多信号检索（语义 + BM25 关键词 + 实体，并行打分后融合）。但**部署环境不连外网**，语义通道需要 embedding 模型服务，不可用；实体链接与图共现需要额外索引，也不在本次范围。因此本次只做能在离线、确定性条件下落地的那一半。
  - 同一套「查询词元对文档词元的覆盖打分」在 `loreRetrieval`、`loreDialogueRetrieval`、`memory/retrieval` 三处各自实现，属结构性问题：算法升级必须只改一处。
  - 本决策落地的同一时段，另一个会话正在做同一方向的 `2026-09-18-bm25-retrieval`（新建 `src/text/bm25.ts` 与 `tokenizeFrequencies`，并已接入 `loreRetrieval`）。本决策因此**收敛到该共享模块**，不另起实现。
- **Decision**：
  - **单一 BM25 实现**：`src/text/bm25.ts`（`buildCorpusStats` + `scoreBm25`）作为全项目唯一的 BM25 打分点，lore 与 memory 都走它；本决策只对 `scoreBm25` 做加法（新增可选 `Bm25Options{k1, b}`，默认值不变，lore 行为零变化）。
  - **记忆流的长度归一化关闭（`MEMORY_BM25_OPTIONS = { b: 0 }`）**：这是测出来的，不是偏好。记忆流里最长的记录恰好是最具体的记录，BM25 的长度惩罚压掉的正是值得召回的那些。IDF 与 TF 饱和保留。
  - **词干归一化**：`src/text/tokenize.ts` 新增 `tokenizeSearchFrequencies`，在既有词频分词（CJK 二元组 + ASCII 整词）之上叠加英文剥后缀形式（`researching` ↔ `research`）。原文形式保留，字面命中永不掉分。这是纯词法检索里替代语义通道的最低成本手段。
  - **通道边界不变**：`tags` / `sourceIds` 仍用集合重叠打分——离散标识符不是自然语言，BM25 的 IDF 与长度归一化不适用。
  - **契约不变**：`score.relevance` 仍是 `[0,1]` 且完全匹配精确等于 1（BM25 的归一化基准取「文档长度等于语料平均长度、每个查询词恰好出现一次」的理想分，`b=0` 时该点恰为 1）；`scoreMemoryRecord(record, query)` 单文档签名不变；排序权威仍是 `finalScore`，不引入第二个排序来源；全流程确定性、零新增依赖、零网络。

- **Consequences**：
  - **正向**：证据召回 LoCoMo @1 +139%、@10 +43%；自有语料「唯一相关但旧且不重要」recall@1 从 75% 到 100%。零新增依赖、零网络、延迟在噪声内、确定性与既有契约全部保持。
  - **代价**：`relevance` 的语义从「查询词覆盖率」变为「BM25 归一化分」，读分数的人需要知道 b=0 是刻意的；`scoreMemoryRecord` 单文档调用的 IDF 语料退化为单条记录，分数低于旧的覆盖率口径（语义上正确，但数值不可与旧版本直接对比）。
  - **未做**：Mem0 的 embedding 语义通道（部署不连外网，需要模型服务决策）；实体链接与图共现——multi-hop 仍是最弱分类（纯词法 26.1%），要提上去得靠图遍历，属独立工程。
  - **并发合并风险**：本决策与另一会话的 `2026-09-18-bm25-retrieval` 在 `src/text/`、`src/lore/loreRetrieval.ts`、`src/memory/retrieval.ts` 上重叠。本决策只做加法且已收敛到对方的共享模块，但对方任务仍未填写验证记录；若其继续改 `src/memory/retrieval.ts` 需人工合并，且这条线应只保留一个写入者。
  - `loreDialogueRetrieval` 尚未接入共享 BM25（对方计划内、未完成）；中文语料上词干归一化是空操作，所以记忆路径与 lore 路径的分词器差异对正史检索无影响。
  - `.claude/specs/memory-governance.md` 的检索成本表已加注最新可复现数据来源，原表保留为历史记录。
