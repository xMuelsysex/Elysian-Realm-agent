# 0001. 按用户档案隔离剧情进度与完整剧情知识

- **Status**：Accepted
- **Context**：项目需要导入 `往世乐土` 与 `致以无瑕之人` 的完整剧情原文，并让角色根据每个用户已经推进到的剧情阶段获得对应知识。现有 Host 以单一用户和单一状态存储为中心，直接增加一个全局剧情时间会导致不同用户之间串用记忆、关系和剧透范围。
- **Decision**：
  - 使用本地用户档案和稳定 `profileId` 区分参与者；档案由后台创建和配置，多个档案存在时由聊天用户自行选择。
  - 剧情进度按用户独立保存；每个用户使用一个按场景 / 页面推进的剧情游标，第一期由后台手动前后调整。
  - 用户的剧情进度、角色记忆、好感度、心情、自我认知和对话历史全部隔离；新档案从零开始，不自动继承现有单用户状态。
  - 全量原文从指定文本站点一次性导入为本地资料快照，运行时不依赖外部网络；原文保留说话角色、旁白、系统、选项和结果等文本类型。
  - 资料按两大章内部的小章节顺序组织。角色只获得当前游标已解锁内容，并遵守场景入场点：角色进入前的对话默认不可知，后续原文明确转述时才可获得前情。
- **Consequences**：
  - 后续存储和聊天请求必须携带或解析用户档案边界，不能继续把所有动态状态视为全局单例。
  - 后台需要提供档案创建 / 配置、剧情游标查看与调整，并让聊天用户能够选择档案。
  - 回退游标必须同步恢复对应节点之后的用户状态，因此需要可定位的状态快照或等价的可回放 / 截断机制。
  - 本地快照保证离线确定性和可复现性，但文本站点更新后需要重新导入并审查版本；完整原文的使用和分发仍需遵守相应授权边界。
